# augur

Word prediction library in Rust, in the spirit of
[Presage](https://presage.sourceforge.io/): given the text around the cursor,
it suggests the next word or completes the current one. It runs on Windows,
Linux and macOS, and has a C API and a header-only C++17 wrapper.

> Status: English prediction from a static n-gram model works end to end,
> from Rust, C and C++. The user model (learning from typed text) and the
> CLI are not implemented yet.

## Layout

| Path | Contents |
|---|---|
| `crates/augur-core` | Traits and types: `Predictor`, `LanguagePack`, `Combiner`, `Suggestion` |
| `crates/augur` | Facade: `Engine`, `EngineBuilder`, `LinearCombiner` |
| `crates/augur-capi` | C API; `include/augur.h` is generated by cbindgen at build time |
| `bindings/cpp` | Header-only C++17 wrapper `augur.hpp` |
| `bindings/tests` | C and C++ (Catch2) SDK tests |
| `crates/augur-text` | Unicode (UAX #29) tokenizer and normalization shared by training and prediction |
| `crates/augur-lang-en` | English language pack |
| `crates/augur-train` | Training tool: Wikipedia dump → corpus → ARPA n-gram model → binary model |
| `crates/augur-lm` | Binary n-gram model format: ARPA import, writer and reader |
| `crates/augur-predictors` | `NgramPredictor`: next-word prediction and completion from an n-gram model |
| `crates/augur-user`, `-cli` | Placeholders for later phases |
| `testdata` | Tiny English model used by the Rust, C and C++ tests |
| `xtask` | Developer tasks |

## Usage

Given a model file (see [Training an English model](#training-an-english-model)):

```rust
use augur::{Context, Engine};

let engine = Engine::from_model("en", "en.bin")?;
for s in engine.predict(Context::past("I live in Lon"), 5) {
    println!("{} {:.3}", s.text, s.prob); // London 0.919, …
}
```

```cpp
#include "augur.hpp"

const augur::Engine engine{"en", "en.bin"};              // throws augur::Error
for (const auto& s : engine.predict("I live in Lon")) {   // text after the cursor and a
    std::cout << s.text << ' ' << s.prob << '\n';          // maximum count are optional
}
```

In C, `augur_engine_new`, `augur_predict` and the `augur_suggestions_*`
accessors do the same; see `crates/augur-capi/include/augur.h`. An engine
may be used from several threads at once.

Suggestions are ranked by the model's back-off probability. Their `prob` is
conditioned on the typed prefix (the probabilities of all words matching
the prefix sum to 1). Casing comes from the model (`London`) plus sentence
starts and "I". The word right after the cursor is not suggested again.

## Building

Requirements: rustup (the pinned toolchain installs automatically), and for
the C/C++ SDK, CMake 3.22+ and a C/C++ compiler.

```sh
cargo xtask ci          # fmt check, clippy, Rust tests, C header check
cargo xtask sdk         # build and test the C/C++ SDK with CMake
```

If `cmake` is not on your `PATH` (e.g. you use the copy bundled with Visual
Studio), point `CMAKE` at it:

```powershell
$env:CMAKE = "C:\Program Files\Microsoft Visual Studio\18\Community\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin\cmake.exe"
cargo xtask sdk
```

### Using from CMake

```cmake
add_subdirectory(path/to/augur)
target_link_libraries(my_app PRIVATE Augur::augur_cpp)   # or Augur::augur_static / Augur::augur_shared
```

An installable `find_package(Augur)` package is planned for phase 4.

## Training an English model

Download a Simple English Wikipedia dump from
<https://dumps.wikimedia.org/simplewiki/> (the
`simplewiki-YYYYMMDD-pages-articles.xml.bz2` file), then:

```sh
cargo run --release -p augur-train -- extract simplewiki-YYYYMMDD-pages-articles.xml.bz2 -o corpus.txt
cargo run --release -p augur-train -- build corpus.txt -o model.arpa
cargo run --release -p augur-train -- compile model.arpa -o en.bin
```

`extract` writes `corpus.txt` (one tokenized sentence per line),
`corpus.casing` (usual capitalization of words such as `London`) and
`corpus.meta` (source file, SHA-1 to compare with Wikimedia's `sha1sums`
file, license and attribution). `build` writes `model.arpa` plus
`model.casing` and `model.meta`. `compile` packs all three into `en.bin`,
the single file augur loads (any ARPA file works, e.g. from KenLM; the
sidecar files are optional).

The binary model holds a sorted vocabulary, one sorted array of
fixed-width records per n-gram order, probabilities and back-off weights
quantized to 8 bits per order, the casing table and the provenance
metadata, each section protected by a CRC-32. The Simple English
Wikipedia model (3-gram, 100k words) compiles from a 134 MB ARPA file to
35 MB and loads in about 25 ms.

Main `build` options (see `--help`):

| Option | Default | Meaning |
|---|---|---|
| `--order` | 3 | N-gram order (1–6) |
| `--smoothing` | `mkn` | `mkn` (modified Kneser-Ney) or `stupid-backoff` |
| `--vocab` | 100000 | Words kept; the rest become `<unk>` |
| `--min-count` | `1,2,2` | Minimum count per order; the last value repeats |
| `--mem` | `1G` | Approximate memory budget; counting spills to disk beyond it |
| `--tmp-dir` | system temp | Where temporary files go |
